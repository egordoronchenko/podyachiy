# Подьячий

Сервис, который превращает записи совещаний, лекций и созвонов в расшифровку с разделением
говорящих, протокол с поручениями и карту протокола. Ставится на свой сервер или компьютер одним
контейнером Docker; люди работают с ним через страницу в браузере, программы и ИИ-клиенты — через API.

Открытый код, лицензия MIT. Сервис бесплатный; платить приходится только поставщику моделей —
за распознавание речи и текст протокола.

![Главная страница: папки, список записей и открытый протокол](site/assets/shot-main-light.webp)

Совещание, люди и суммы на снимках вымышлены.

- **Установка и сопровождение** (сеть, HTTPS, почта, домен, резервная копия, обновление) —
  [install/README.md](install/README.md); то же одним файлом с оглавлением —
  [site/podyachiy-install.html](site/podyachiy-install.html).
- **Как пользоваться** — [руководство пользователя](docs/guide/README.md) со снимками экрана
  (одним файлом — [site/podyachiy-guide.html](site/podyachiy-guide.html)) и справка внутри сервиса:
  пункт «Справка» в меню.
- **Визитка и демонстрация** — [site/podyachiy.html](site/podyachiy.html) и [site/podyachiy-demo.html](site/podyachiy-demo.html): два файла, открываются с диска; в демонстрации настоящие страницы сервиса на выдуманных записях.

## Что делает

1. Принимает запись — видео или звук, файлом до 4 ГБ, через страницу (с докачкой после обрыва),
   через API или из папки на диске.
2. Извлекает звук и отправляет его на распознавание: модель возвращает текст, время каждого
   слова и метку говорящего.
3. Определяет тип записи — совещание, лекция, созвон с заказчиком, постановка задачи — и пишет
   протокол по шаблону этого типа. У каждого решения и каждой задачи стоит метка времени:
   щелчок по ней перематывает запись на нужное место.
4. Для совещаний поручения выписывают несколько моделей независимо — так их теряется меньше.
5. Строит карту протокола; протокол, карта и расшифровка скачиваются одним HTML-файлом.

Ещё есть: реестр поручений по всем совещаниям с отметкой «выполнено», сроками и выгрузкой в CSV;
незакрытые поручения прошлого совещания в конце нового протокола — в папках, отмеченных как серия совещаний;
поиск по протоколам и расшифровкам; экспорт протокола в DOCX и PDF; ручные подписи говорящих;
свои шаблоны протоколов, свои типы записей и словарь терминов; словарь участников и сокращений
на папку и на отдельную запись — по нему в протоколе стоят полные ФИО и правильные сокращения; письмо «запись готова» и отправка
протокола на почту; отчёт о расходах по папкам, людям и записям — на странице и файлом Excel, CSV или PDF; светлая и тёмная тема.

## Быстрый запуск

Три пути, от простого к подробному:

- **для себя**, на своём компьютере, без входа — [install/personal.md](install/personal.md):
  Docker Desktop, ключ поставщика, две строки в `.env`;
- **руками ИИ-агента** (Claude Code, Cursor, Codex) — для себя или для организации: скажите
  агенту «Установи Подьячий по инструкции install/AI-INSTALL.md» —
  [install/AI-INSTALL.md](install/AI-INSTALL.md);
- **для организации** — [install/README.md](install/README.md).

Самый короткий путь для разработчика — сборка из исходников. Нужны Docker с плагином compose и
ключ поставщика моделей.

```bash
git clone https://github.com/egordoronchenko/podyachiy.git
cd podyachiy
cp install/.env.example .env
```

В файле `.env` заполните две строки:

```
OPENAI_API_KEY=ключ поставщика моделей
ADMIN_PASSWORD=пароль администратора сервиса
```

Запустите:

```bash
docker compose up -d --build
```

Откройте <http://localhost:8081> и войдите под логином `admin` с паролем из `.env`.

Собирать образ самому не обязательно: в папке `install` лежит `compose.yml`, который берёт
готовый образ `egordoronchenko/podyachiy`, — порядок описан в [install/README.md](install/README.md).

### Ключ поставщика и цена обработки

Сервис ходит к моделям через шлюз с OpenAI-совместимым API. Подойдёт любой из двух:

| Поставщик | Адрес (`OPENAI_BASE_URL`) | Где взять ключ | Оплата |
|---|---|---|---|
| OpenRouter | `https://openrouter.ai/api/v1` (по умолчанию) | openrouter.ai → Keys | в долларах |
| RouterAI | `https://routerai.ru/api/v1` | routerai.ru | в рублях |

Достаточно одного; второй можно задать запасным (`BACKUP_BASE_URL`, `BACKUP_API_KEY`) — сервис
перейдёт на него, если основной не отвечает.

Ориентир по ценам из карточек моделей: на модели распознавания по умолчанию
(`elevenlabs/scribe-v2`) час записи стоит порядка 0,15–0,25 $ через OpenRouter или 17–30 ₽ через
RouterAI; большая часть суммы — распознавание речи. Цены поставщики меняют — сверяйте в их
карточках моделей. Сколько стоила каждая запись, сервис показывает администратору в разделах
«Обработка» и «Расходы»; остальным пользователям суммы не показываются.

## Два режима

Режим задаётся строкой `MODE` в `.env`.

| | Корпоративный — `MODE=corporate` | Личный — `MODE=personal` |
|---|---|---|
| Для кого | организация, несколько человек | один человек на своём компьютере |
| Вход | обязателен | нет |
| Папки и права | у каждого личная папка; общие папки с раздельными правами: чтение, загрузка, администрирование | все записи видны сразу |
| Заявки на доступ, почта, ключи доступа | есть | нет |
| Вход через домен, свой логотип | есть | нет |
| Доступ по сети | во внутренней сети | **нельзя**: сервис отдаст всё любому, кто до него достанет |

## Интеграция с ИИ-клиентами и программами

Всё, что видно на странице, доступно запросами `/api/v1/…`: записи, протоколы, поручения полями,
поиск, загрузка, подписи говорящих, расходы (их — только администратору сервиса). Описание
сервис отдаёт сам:

- **страница «API»** — `/api`: как это работает и все методы по разделам — что делает, кому открыт,
  платный ли, параметры, примеры для bash и PowerShell, пример ответа, отказы; фильтр по методам
  и кнопка «Выполнить» для чтения своим ключом;
- **машинное описание** — `GET /api/v1/openapi.json` (OpenAPI 3.1, без входа): по нему одному
  программа или модель вызовет любой метод. Свои поля: `x-rights` — какое право нужно, `x-key` —
  каким ключом открыт, `x-paid` — ведёт ли вызов к платной обработке;
- **текст для модели** — `GET /api/v1` (Markdown, по входу).

Все три собраны из одного источника — [app/apidoc.py](app/apidoc.py), поэтому не расходятся;
имена и типы параметров берутся из самих маршрутов. Встроенные страницы FastAPI (`/docs`,
`/redoc`) выключены: им нужен интернет, а описывают они и внутренние адреса.

Вход — в каждом запросе: ключ доступа (`Authorization: Bearer stg_…`) или логин и пароль
(HTTP Basic). Ключ каждый выпускает себе сам, в меню под своим именем; права ключа — права
человека. Удалять записи ключом нельзя.

```bash
curl -H "Authorization: Bearer $KEY" "http://localhost:8081/api/v1/tree"
curl -H "Authorization: Bearer $KEY" -G "http://localhost:8081/api/v1/record" \
  --data-urlencode "file=Проекты/Планёрка.mp4"
```

Примеры написаны для bash в Linux и macOS. В Windows — PowerShell и `curl.exe`: русские буквы
в адресе кодируются `[uri]::EscapeDataString`, тело запроса с русскими буквами уходит из файла
в UTF-8 (в Git Bash под Windows `curl` получает русские буквы искажёнными):

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8      # чтобы русский текст ответа читался в окне
$file = [uri]::EscapeDataString("Проекты/Планёрка.mp4")
curl.exe -sS -H "Authorization: Bearer $env:KEY" "http://localhost:8081/api/v1/record?file=$file"
```

Готовый пример для обеих оболочек есть у каждого метода на странице `/api`.

Для ИИ-клиентов с терминалом (Claude Code, Cursor, Codex) есть навык: сервис раздаёт его сам по
адресу `/skill`. Человек копирует фразу из справки («Интеграция с ИИ»), вставляет в чат клиента —
и дальше просит обычными словами: «найди протокол вчерашней планёрки», «какие поручения на мне
не закрыты». Исходники навыка — [app/skill/](app/skill/).

## Вход через домен

В корпоративном режиме люди могут входить логином и паролем домена (Active Directory): сервис
проверяет их у контроллера домена по LDAPS и при первом входе сам заводит человека. Кого пускать
и кто администратор, решают группы домена. Работает только по HTTPS. Проверено на контроллере
Samba 4; на Active Directory под Windows Server не проверялось. Настройка —
[install/README.md](install/README.md), раздел «Вход через домен».

## Документация

| Что | Для кого | Где лежит |
|---|---|---|
| Справка | тот, кто работает в сервисе | `app/static/help.html` — страница `/help`; разделы показываются по режиму и роли |
| Руководство пользователя | новые пользователи, руководство | источник — `docs/guide/README.md`, снимки — `docs/guide/shots/`; собранный файл — `site/podyachiy-guide.html` |
| Инструкция по установке | администратор | источник — `install/README.md`; собранные файлы — `site/podyachiy-install.html` и `app/static/install-guide.html` (страница `/install-guide` в сервисе) |
| Установить для себя | один человек на своём компьютере | источник — `install/personal.md`; собранный файл — `site/podyachiy-personal.html` |
| Установка ИИ-агентом | ИИ-агент человека: ставит сервис для себя или для организации | `install/AI-INSTALL.md` (только Markdown) |
| Описание API | программы и ИИ-клиенты | `app/apidoc.py` — страница `/api` и `/api/v1/openapi.json` |

Собранные файлы самодостаточны — стили, шрифт, логотип и снимки внутри — и лежат в репозитории.
Правят только источники, затем пересобирают:

```bash
python tools/docs_build.py            # четыре файла из install/README.md, install/personal.md и docs/guide/README.md
python tools/docs_build.py --check    # только проверить, что собранное не отстало
```

Сценарию нужна только стандартная библиотека Python. Тест `tests/test_docs.py` падает, если
собранные файлы отстали от источников, если внутренняя ссылка никуда не ведёт или файл что-то
просит из сети. Снимки экрана руководства снимаются с одноразового стенда на выдуманных данных:
шаги — в начале `tools/guide_shots.mjs`. Демонстрация пересобирается отдельно —
`python tools/demo_page.py`.

## Разработка и тесты

Python 3.12, FastAPI, uvicorn, httpx; ffmpeg — отдельной программой. Страницы — обычные HTML,
CSS и JavaScript без сборки. Состояние — база SQLite `state/podyachiy.db` (`app/db.py`).

```bash
docker build -t podyachiy:dev .
docker run --rm -v "$PWD:/w" -w /w podyachiy:dev \
  sh -c "pip install -q -r requirements-dev.txt && python -m pytest -q -p no:cacheprovider"
python -m compileall -q app
```

Тесты наружу не ходят: поставщики моделей, почта и домен заменены заглушками.

## Ограничения

- **Данные уходят поставщику моделей.** Звук и текст записей отправляются выбранному вами
  поставщику и дальше — владельцам моделей, чьи серверы находятся за границей. Если правила
  организации это запрещают, сервис не подойдёт.
- **Говорящих разделяет модель и ошибается.** Чем больше людей и чем длиннее запись, тем чаще
  реплика достаётся не тому. Людей по голосу сервис не узнаёт: имена он берёт из разговора как
  догадку, остальных подписывает человек.
- **Протокол пишет языковая модель.** Поручения иногда теряются, фамилии и термины искажаются.
  Важное сверяют по записи — для этого у решений и задач стоят метки времени.
- **Для внутренней сети.** На публикацию в интернете сервис не рассчитан: двухфакторного входа
  нет. По HTTP пароли идут открыто — для шифрования перед сервисом ставится прокси.
- **Интерфейс и шаблоны — на русском.**
- **Поддержки нет.** Сервис делает один человек в свободное время и распространяет его «как есть»,
  без гарантий.
