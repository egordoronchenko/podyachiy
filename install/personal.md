# «Подьячий»: установить для себя

Короткая инструкция для одного человека: сервис ставится на ваш компьютер и открывается только
с него, входа и паролей нет. Программировать не нужно — понадобится скопировать несколько файлов
и выполнить несколько команд.

Для организации, где сервисом пользуются несколько человек и входят по паролю, — подробная
[инструкция администратора](README.md). Поручить установку своему ИИ-агенту (Claude Code, Cursor,
Codex) можно по файлу `install/AI-INSTALL.md`: скажите агенту «Установи Подьячий по инструкции
install/AI-INSTALL.md».

Как это работает: вы загружаете запись совещания, лекции или созвона на страницу в браузере,
сервис отправляет звук на распознавание и через несколько минут показывает расшифровку
с разделением говорящих, протокол и карту протокола. Распознавание и протокол делают внешние
модели через поставщика — RouterAI или OpenRouter: **звук и текст записей уходят поставщику и
владельцам моделей, в том числе за границу.** Сам сервис бесплатный, платите только поставщику.

---

## Что понадобится

| Что | Подробности |
|---|---|
| Компьютер | Windows 10 или 11 (64 бита), macOS или Linux; 8 ГБ памяти — с запасом. Видеокарта не нужна |
| Docker Desktop | бесплатная программа, в которой работает сервис (ниже — как поставить) |
| Ключ поставщика | RouterAI (оплата в рублях) или OpenRouter (в долларах); на счёте должны быть деньги |
| Интернет | к поставщику и к Docker Hub — скачать образ сервиса |
| Место на диске | Docker Desktop и образ сервиса — около 5 ГБ; записи — сколько весят ваши файлы, плюс 30 МБ на час записи |
| Файлы установки | `compose.yml` и `.env.example` из папки `install` комплекта; если готового образа в реестре нет — весь архив с исходниками |

Сколько весят записи: видео совещания — обычно 0,5–2 ГБ за час, звук mp3 — 30–60 МБ за час.
Сервис ничего не удаляет сам: место освобождаете вы, удаляя записи на странице.

## Ключ поставщика

Достаточно одного поставщика. Модели у обоих одни и те же, цены разные.

**RouterAI** — российский, оплата в рублях.

1. Зарегистрируйтесь на <https://routerai.ru>.
2. Пополните баланс в личном кабинете.
3. Там же создайте ключ API и скопируйте его.

**OpenRouter** — зарубежный, оплата в долларах (картой зарубежного банка или криптовалютой).

1. Зарегистрируйтесь на <https://openrouter.ai>.
2. Пополните счёт: Settings → Credits.
3. Создайте ключ: Settings → Keys → Create Key. Ключ начинается с `sk-or-` и показывается один раз —
   сразу скопируйте его. Ключу можно задать предел расходов: перерасход тогда невозможен.

Ключ — как пароль от кошелька: никому его не пересылайте и не вставляйте в чаты.

## Поставить Docker Desktop

**Windows.**

1. Скачайте Docker Desktop с <https://www.docker.com/products/docker-desktop/> и запустите
   установщик. Нужны права администратора компьютера. Галочку «Use WSL 2» оставьте.
2. Перезагрузите компьютер, если установщик попросит.
3. Запустите Docker Desktop из меню «Пуск», примите соглашение. Входить в учётную запись Docker
   не нужно — окно входа можно пропустить. Подождите, пока внизу окна появится «Engine running».

Если Docker Desktop пишет про WSL — откройте PowerShell от имени администратора и выполните
`wsl --update` (на старой Windows 10 — `wsl --install`), затем перезагрузите компьютер. Если пишет,
что виртуализация не включена (Virtualization support not detected), её включают в настройках
BIOS — это уже вопрос к тому, кто разбирается в вашем компьютере. Подробно — в инструкции
Docker: <https://docs.docker.com/desktop/setup/install/windows-install/>.

**macOS.** Скачайте Docker Desktop для своего процессора (Apple или Intel) с той же страницы,
перетащите в «Программы», запустите.

**Linux.** Поставьте Docker Engine с плагином compose по инструкции
<https://docs.docker.com/engine/install/>.

Проверка — в терминале (на Windows — PowerShell):

```bash
docker version
docker compose version
```

Обе команды должны ответить номерами версий, у первой — с разделом `Server`. Если ответ «docker
не является командой» — закройте и откройте терминал заново; если ругается на подключение —
Docker Desktop не запущен.

## Папка и два файла

Создайте папку, в которой сервис будет жить, например `C:\Users\<ваше имя>\Podyachiy` на Windows
или `~/Podyachiy` на macOS и Linux. Не кладите её в OneDrive, Dropbox и другие облачные папки.
Положите в неё из папки `install` комплекта:

- `compose.yml`;
- `.env.example` — и переименуйте копию в `.env` (имя начинается с точки, расширения нет).

В Windows включите показ расширений (Проводник → «Вид» → «Показать» → «Расширения имён файлов»),
иначе легко получить `.env.txt` вместо `.env`.

## Что поменять в `.env`

Откройте `.env` в текстовом редакторе (Блокнот подойдёт; сохранять в кодировке UTF-8). Файл
длинный, но для личного режима нужно поменять только эти строки:

```ini
MODE=personal
OPENAI_API_KEY=ваш-ключ-поставщика
```

Если ключ от **RouterAI**, поменяйте ещё адрес поставщика (по умолчанию в файле — OpenRouter):

```ini
OPENAI_BASE_URL=https://routerai.ru/api/v1
```

Ключ вписывается сразу после знака `=`, без пробелов и кавычек. Остальное не трогайте:

- `ADMIN_PASSWORD` оставьте пустым — в личном режиме входа нет и пароль не нужен;
- `BIND=127.0.0.1` оставьте как есть: страница открывается только с этого компьютера. В личном
  режиме сервис без входа отдаёт всё любому, кто до него достанет, — в сеть его открывать нельзя;
- `PORT=8081` поменяйте, только если этот порт уже занят другой программой.

Что ещё можно настроить (папки на другом диске, запасной поставщик, язык записей) — таблица
в [разделе «Настройки .env»](README.md#3-настройки-env) инструкции администратора.

## Образ сервиса

Сервис — один контейнер Docker из образа `egordoronchenko/podyachiy`. Образ берётся одним из двух
способов.

**Готовый образ из реестра Docker Hub.** Ничего делать не нужно: первый запуск (ниже) скачает
его сам, около 1 ГБ.

**Сборка из исходников** — если готового образа в реестре нет: запуск отвечает `not found`,
`pull access denied` или `repository does not exist`. Тогда нужен весь архив с исходниками. Распакуйте его в
отдельную папку (не в папку сервиса), откройте в ней терминал — там, где лежат `Dockerfile` и
папка `app`, — и соберите образ:

```bash
docker build -t egordoronchenko/podyachiy:latest .
```

Сборка идёт 3–10 минут и скачивает из интернета основу образа, ffmpeg и библиотеки Python.
Закончилась строкой с `naming to docker.io/egordoronchenko/podyachiy:latest` — образ готов.
Архив после этого можно удалить: сервису он не нужен.

## Запуск

В папке сервиса (там, где `compose.yml` и `.env`) выполните:

```bash
docker compose up -d
```

Через полминуты проверьте: `docker compose ps` — в столбце состояния должно быть
`Up … (healthy)`.

Откройте в браузере <http://localhost:8081> (или свой порт). Страница откроется сразу, без входа.

Проверьте ключ: в меню слева «Управление → Обработка», кнопка **«Проверить ключ»**. Запрос
бесплатный. Ответ «ключ принят» — всё готово. «Ключ не принят (HTTP 401)» — ключ вписан с
ошибкой или он от другого поставщика: исправьте `.env` и выполните `docker compose up -d`.
Та же проверка идёт при каждом запуске сервиса — её итог есть строкой в «Журнале работы»
на той же странице.

После первого запуска в папке сервиса появятся подпапки:

```
inbox\      ваши записи, как вы их загрузили
outbox\     расшифровки, протоколы, карты, звук для проигрывателя, журнал работы
state\      база сервиса: что уже обработано, расходы, словари
backup\     резервные копии
prompts\    шаблоны протоколов и словарь терминов
```

Не удаляйте их, особенно `state`: без базы сервис сочтёт все записи новыми и обработает их
заново — за деньги.

## Первая запись

Нажмите **«Загрузить запись»** и выберите короткий файл на две-три минуты — видео или звук. Через
полминуты запись появится в списке со статусом «обрабатывается», ещё через минуту-две —
«готово». Откройте её: протокол, карта, расшифровка; щелчок по метке времени перематывает запись.

Записи можно класть и прямо в папку `inbox` — сервис заметит их сам. Подпапки в `inbox` — это папки
на странице.

Как пользоваться дальше — пункт «Справка» в меню сервиса и
[руководство пользователя](../docs/guide/README.md).

## Сколько стоит

Ориентир по карточкам моделей: на модели распознавания по умолчанию час записи стоит порядка
0,15–0,25 $ через OpenRouter или 17–30 ₽ через RouterAI; большая часть — распознавание речи.
Цены поставщики меняют. Сколько стоила каждая запись, показывает раздел «Управление → Расходы»;
окончательные цифры — в кабинете поставщика.

Платно всё, что отправляет запись на обработку: загрузка, ручной запуск с галкой «перезаписать»
(распознаётся заново). Пересборка протокола без перезаписи стоит копейки — платится только текст.
Просмотр, поиск, скачивание, правка подписей говорящих — бесплатно.

## Остановить, обновить, удалить

Все команды — в папке сервиса.

| Что | Команда |
|---|---|
| Остановить | `docker compose stop` |
| Запустить снова | `docker compose start` |
| Применить правку `.env` | `docker compose up -d` |
| Посмотреть журнал контейнера | `docker compose logs --tail 100` |

Сервис запускается сам вместе с Docker Desktop. Чтобы Docker Desktop запускался при входе в
систему, в его настройках (Settings → General) включите «Start Docker Desktop when you sign in».

**Обновить.** Сначала сделайте резервную копию:
`docker compose exec podyachiy python -m app.backup create` — архив ляжет в папку `backup`
(подробно — [раздел «Резервная копия»](README.md#12-резервная-копия-и-восстановление)). Затем:

- готовый образ — `docker compose pull`, потом `docker compose up -d`;
- сборка из исходников — соберите образ из нового архива той же командой `docker build`, потом
  `docker compose up -d`.

Записи, протоколы, база и ваши правки шаблонов при обновлении остаются. Подробно —
[раздел «Обновление версии»](README.md#13-обновление-версии).

**Удалить.** `docker compose down` убирает контейнер; папки с записями и протоколами остаются.
Чтобы убрать и образ: `docker image rm egordoronchenko/podyachiy:latest`. Папку сервиса удаляйте
сами, когда сохраните из неё всё нужное: вместе с ней пропадут записи и протоколы.

## Частые проблемы

| Что видно | Почему | Что делать |
|---|---|---|
| `docker` не является командой | Docker Desktop не установлен или терминал открыт до установки | поставить Docker Desktop, открыть терминал заново |
| `error during connect`, `Cannot connect to the Docker daemon`, `dockerDesktopLinuxEngine` | Docker Desktop не запущен | запустить его и дождаться «Engine running» |
| Docker Desktop пишет про WSL | не установлен или устарел WSL | PowerShell от имени администратора: `wsl --update`, перезагрузка |
| `not found`, `pull access denied`, `repository does not exist` при запуске | готового образа в реестре нет | собрать из исходников (см. «Образ сервиса») |
| `TLS handshake timeout`, `i/o timeout` при скачивании образа или сборке | нет доступа к Docker Hub | проверить интернет, VPN; попросить образ файлом и загрузить его: `docker load -i файл.tar` |
| `port is already allocated`, `address already in use` | порт 8081 занят другой программой | в `.env` поставить `PORT=8082` (или другой свободный), `docker compose up -d` |
| Страница просит войти | в `.env` не `MODE=personal` или контейнер не пересоздан после правки | исправить `.env`, `docker compose up -d` |
| «Ключ не принят (HTTP 401)» | ключ неверный, отозван или от другого поставщика | проверить ключ и `OPENAI_BASE_URL`, `docker compose up -d` |
| «Поставщик отказал из-за баланса (HTTP 402)» | кончились деньги на счёте | пополнить счёт у поставщика |
| Запись в ошибке | причина написана под записью в «Управление → Обработка» | устранить причину, запустить запись там же |
| После обновления старая страница | кэш браузера | Ctrl+F5 |

Остальные сообщения и что с ними делать — [раздел «Логи и что смотреть при
сбое»](README.md#14-логи-и-что-смотреть-при-сбое) инструкции администратора.
