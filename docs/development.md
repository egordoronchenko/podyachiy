# Подьячий: разработка

Устройство репозитория, тесты, сборка документации, демонстрации и образа, выпуск версии. Как
прислать правку — [CONTRIBUTING.md](../CONTRIBUTING.md).

## Из чего сделан

Python 3.12, FastAPI, uvicorn, httpx; ffmpeg — отдельной программой. Страницы — обычные HTML,
CSS и JavaScript без сборки. Состояние — база SQLite `state/podyachiy.db` (`app/db.py`).

## Тесты

```bash
docker build -t podyachiy:dev .
docker run --rm -v "$PWD:/w" -w /w podyachiy:dev \
  sh -c "pip install -q -r requirements-dev.txt && python -m pytest -q -p no:cacheprovider"
python -m compileall -q app
```

Тесты наружу не ходят: поставщики моделей, почта и домен заменены заглушками. В GitHub Actions
те же тесты идут на каждую правку в `master` и на каждый запрос на слияние
([.github/workflows/tests.yml](../.github/workflows/tests.yml)).

## Документация: источники и собранные файлы

| Что | Для кого | Где лежит |
|---|---|---|
| Справка | тот, кто работает в сервисе | `app/static/help.html` — страница `/help`; разделы показываются по режиму и роли |
| Руководство пользователя | новые пользователи, руководство | источник — `docs/guide/README.md`, снимки — `docs/guide/shots/`; собранный файл — `site/podyachiy-guide.html` |
| Инструкция по установке | администратор | источник — `install/README.md`; собранные файлы — `site/podyachiy-install.html` и `app/static/install-guide.html` (страница `/install-guide` в сервисе) |
| Установить для себя | один человек на своём компьютере | источник — `install/personal.md`; собранный файл — `site/podyachiy-personal.html` |
| Установка ИИ-агентом | ИИ-агент человека: ставит сервис для себя или для организации | `install/AI-INSTALL.md` (только Markdown) |
| Описание API | программы и ИИ-клиенты | `app/apidoc.py` — страница `/api` и `/api/v1/openapi.json` |

Собранные файлы самодостаточны — стили, шрифт, логотип и снимки внутри — и лежат в репозитории.
Правят только источники, затем пересобирают:

```bash
python tools/docs_build.py            # четыре файла из install/README.md, install/personal.md и docs/guide/README.md
python tools/docs_build.py --check    # только проверить, что собранное не отстало
```

Сценарию нужна только стандартная библиотека Python. Тест `tests/test_docs.py` падает, если
собранные файлы отстали от источников, если внутренняя ссылка никуда не ведёт или файл что-то
просит из сети. Номер версии из `VERSION` тоже попадает в собранные файлы: после его смены —
пересобрать.

**Снимки экрана руководства** снимаются с одноразового стенда на выдуманных данных — никогда
с рабочей установки. Шаги — в начале [tools/guide_shots.mjs](../tools/guide_shots.mjs).

**Демонстрация** `site/podyachiy-demo.html` — настоящие страницы сервиса на выдуманных записях
(`tools/demo_data`), открывается с диска без сервера. Пересобирается отдельно после правки страниц
или записей:

```bash
python tools/demo_page.py
```

## Образ на Docker Hub

Образ `egordoronchenko/podyachiy` собирается и публикуется только вручную: в репозитории на GitHub —
Actions → «Образ» → Run workflow, в списке выбрать ветку или тег
([.github/workflows/image.yml](../.github/workflows/image.yml)). Сам тег и выпуск на GitHub образ
не публикуют.

- с тега `vX.Y.Z` — теги образа `:X.Y.Z`, `:X.Y` и `:latest`; с предварительного выпуска
  `vX.Y.Z-rc1` — без `:latest`;
- с ветки `master` — `:latest`;
- и при каждом запуске — `:sha-<коммит>` (семь знаков идентификатора коммита).

Образ публикуется, только если в нём проходят тесты. Нужны два секрета репозитория:
`DOCKERHUB_USERNAME` и `DOCKERHUB_TOKEN` (Settings → Secrets).

## Выпуск версии

1. Номер — в `VERSION`; что изменилось — новый раздел в [CHANGELOG.md](../CHANGELOG.md).
2. Пересобрать документы (`python tools/docs_build.py`) и прогнать тесты.
3. Коммит, тег `vX.Y.Z`, выпуск на GitHub (Releases): текст — из CHANGELOG, в конце — строка про
   образ (`docker pull egordoronchenko/podyachiy:X.Y.Z`) и как обновить установку.
4. Образ — Actions → «Образ» → Run workflow с тега `vX.Y.Z`.
5. В корневом README — номер выпуска в ссылке на `install/AI-INSTALL.md` для агента.
